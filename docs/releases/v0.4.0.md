brAIn dump now records the Gazepoint GP3 HD as well as the GP3, through
[OpenGP3](https://github.com/itubrainlab/opengp3) 0.4.0.

## Gazepoint GP3 HD

- **On this computer.** OpenGP3 drives either eye tracker and brAIn dump uses
  whichever is plugged in. The GP3 HD runs at 150 Hz by default. Its rate
  (150 or 60 Hz) is set in the GP3 device's settings, under **GP3 HD rate**.
  The GP3 always runs at 60 Hz.
- **Over the Open Gaze API.** A GP3 HD served by `opengp3 server` or Gazepoint
  Control is recognised from its `PRODUCT_ID`, at the rate the server reports.
- **BIDS.** The eye-tracking sidecars give the model that recorded
  (`ManufacturersModelName` `GP3` or `GP3 HD`) and its frame rate
  (`SamplingFrequency`). The device page and the status line show the model
  and its rate.
- The session pipeline is laid out for the model last connected. The first time
  you connect a GP3 HD, the pupil plot shows about 4 s instead of 10 s until
  you reconnect. The recording is not affected.

## Windows driver

OpenGP3 now uses [UsbDk](https://github.com/daynix/UsbDk/releases) when it is
installed, and recommends it. UsbDk leaves Gazepoint's driver in place, so
Gazepoint Control keeps working, though not at the same time as brAIn dump. A
WinUSB driver bound with Zadig still works. For the GP3 HD, bind it to the
composite device `1E10 3300`.

## Changes

- OpenGP3 0.4.0, which also brings the GP3 HD's bright/dark-pupil tracking,
  physical screen sizes from the operating system on Windows and Linux, and a
  Linux USB rule covering every Gazepoint camera.

## Install

The Windows zip, the macOS DMG (Apple Silicon, macOS 14+) or the Linux tarball
(x86_64, glibc 2.34+). The first launch downloads g.Pype 4.2, g.tec's drivers
(gtec-unicorn, gtec-gds), OpenGP3, NDI and the other libraries from PyPI.
